# VDSina — кастомная интеграция Home Assistant

Версия 1.0.3. Создана по образцу приложенной интеграции Webhost1: настройка через интерфейс, координатор данных, сенсоры серверов с атрибутами и кнопка обновления. Интервал по умолчанию **60 минут**.

В 1.0.1 исправлена ошибка AttributeError при добавлении сенсоров без единицы измерения в HA 2026.3.3. Сенсор «Дата прогноза отключения» имеет device_class date и возвращает дату YYYY-MM-DD. Для обновления замените файлы custom_components/vdsina и перезапустите HA; удалять интеграцию и вводить токен заново не требуется.

## Установка

1. Из архива скопируйте папку `custom_components/vdsina` в `/config/custom_components/vdsina` на вашей HA.
2. Перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы → Добавить интеграцию → VDSina**.
4. Выберите **userapi.vdsina.com** для вашей панели **cp.vdsina.com**. Другой доступный вариант, userapi.vdsina.ru, предназначен для аккаунта панели .ru.
5. Введите постоянный API-токен из сведений пользователя панели VDSina и оставьте интервал **60 минут**.

В configuration.yaml и secrets.yaml ничего добавлять не требуется. Токен сохраняется в настройках интеграции HA. Если уже установлен предыдущий YAML-пакет из vdsina-ha.zip, уберите его подключение и старую карточку, чтобы не дублировать запросы и сущности. Интеграцию Webhost1 менять не нужно.

Папка должна содержать именно `/config/custom_components/vdsina/manifest.json`, без дополнительной вложенной папки vdsina-custom. Если VDSina не появилась после перезапуска, обновите страницу браузера и проверьте журнал HA на сообщения custom_components.vdsina.

## Новое в 1.0.3 — статистика как в панели

Для каждого VPS есть общий расход, лимит, процент использования, входящий и исходящий трафик за текущий календарный месяц. Расходы показаны в GiB (1 GiB = 1024³ байт), лимит в TiB (1 TiB = 1024⁴ байт). Такой пересчёт соответствует соотношению чисел на присланном скриншоте: 130,7 / 1024 × 100 ≈ 12,76%. Панель подписывает эти величины как GB/TB; в HA используются точные обозначения двоичных единиц GiB/TiB.

Общий расход берётся из bandwidth.current_month, лимит — строго из data.traff.bytes ответа server/ID. Процент рассчитывается по этим двум значениям. Неизвестный или нулевой лимит не подменяется предположением: процент будет unknown.

Входящий и исходящий интернет-трафик суммируются по vnet_rx / vnet_tx почасовых блоков server.stat/ID. Запрос задаёт период с первого числа месяца 00:00:00 до момента опроса в Europe/Moscow. Локальный сетевой трафик не учитывается. Общий расход и сумма направлений могут расходиться из-за задержки почасовой статистики и округления. Это не скорость соединения.

Если статистика отсутствует или запрос статистики завершился ошибкой, направления показывают unknown, остальные данные аккаунта сохраняют работоспособность. Причина находится в атрибуте traffic_statistics_error. При ошибке общего опроса сенсоры по-прежнему становятся unavailable.

Если существующий сенсор использования трафика продолжает показывать GB после обновления, откройте настройки этой сущности и выберите GiB: HA может сохранять ранее выбранную единицу. Существующая история в GB остаётся корректной, единицы различаются и поддерживают пересчёт. Атрибуты *_gb сохраняются для совместимости, новые *_gib используют двоичные единицы.

## Настройки

В меню интеграции **Настроить** доступны интервал 5–1440 минут и необязательное поле нового API-токена. Пустое поле оставляет текущий токен. При изменении параметров интеграция перезагружается.

Кнопка **Обновить данные** выполняет внеочередной опрос. Первый опрос выполняется при добавлении/запуске HA; при сетевых сбоях HA может повторить попытку раньше обычного интервала. 60 минут — интервал штатного опроса, не запрет на первоначальный опрос, восстановление и ручное обновление.

Если токен станет недействительным, HA запросит повторную авторизацию. Токен другого аккаунта не заменит данные существующих серверов: добавьте другой аккаунт отдельно.

## Сущности

Устройство аккаунта VDSina содержит:

- Баланс, бонусный и партнёрский балансы.
- Прогноз отключения аккаунта, оставшиеся календарные дни, количество серверов.
- Время последнего успешного обновления.
- Кнопку обновления.

Для каждого VPS автоматически создаются девять сенсоров:

| Сенсор | Состояние |
|---|---|
| `<имя VPS> баланс` | Общий основной баланс аккаунта, как в Webhost1 |
| `<имя VPS> статус` | active / new / block / notpaid / неизвестный статус API |
| `<имя VPS> IP` | Основной адрес; полный список находится в атрибуте ips |
| `<имя VPS> тариф` | Название тарифного плана |
| `<имя VPS> использование трафика` | Расход за текущий месяц в GiB |
| `<имя VPS> лимит трафика` | Месячный лимит в TiB |
| `<имя VPS> использовано трафика в процентах` | Общий расход / лимит × 100 |
| `<имя VPS> входящий трафик` | Получено из интернета за текущий месяц в GiB |
| `<имя VPS> исходящий трафик` | Отправлено в интернет за текущий месяц в GiB |

Сенсор сервера содержит атрибуты:

| Атрибут | Значение |
|---|---|
| provider | VDSina |
| IP, ips | Основной и все возвращённые IP |
| Order, server_id | Стабильный ID сервера VDSina |
| due_date, forecast | Прогноз отключения аккаунта в отображаемом и ISO-формате |
| days_left, message | Дни до прогноза и текст для ваших уведомлений |
| status, status_text | Статус услуги и выполняемая операция |
| balance, currency | Основной баланс и валюта |
| tariff, datacenter, country | Тариф и размещение |
| hostname, os | Имя хоста и ОС |
| cpu, ram, disk, traffic_limit | Выделенные ресурсы из API; RAM и диск в GB, лимит трафика в TB |
| bandwidth | Трафик за текущий/предыдущий месяц в байтах, если API возвращает |
| service_end | Срок услуги из API |
| autopay, autoprolong, autorun | Автопродление и автоматический запуск |
| last_update, execution_seconds | Время и длительность последнего успешного опроса |

Баланс в каждом серверном сенсоре — **один и тот же баланс аккаунта**; складывать эти значения нельзя. `due_date` и `message` тоже относятся к прогнозу всего аккаунта, а не к отдельному серверу. `service_end` хранится отдельно: он не заменяет прогноз отключения. Для сравнения дней используется часовой пояс API Europe/Moscow.

Сущности привязаны к ID аккаунта и сервера, а не к позиции в списке. Новые VPS обнаруживаются при следующем опросе. Удалённые/исчезнувшие VPS становятся недоступными; история их сущностей сохраняется. Удалённые услуги со статусом deleted не учитываются в количестве серверов.

Автоматизации уведомлений не создаются автоматически; атрибут message можно использовать в вашей существующей автоматизации, как для Webhost1.

Если API не возвращает баланс или прогноз, значение будет unknown, а не ноль. Если опрос неуспешен, сенсоры становятся unavailable. active — статус услуги у VDSina; он не проверяет работу WireGuard, SSH или приложений на VPS.

## Иконки

MDI-иконки уже заданы в коде: wallet, wallet-giftcard, handshake, calendar-alert, calendar-clock, server-network, server, ip-network, refresh, update.

В `custom_components/vdsina/brand/` находятся изображения бренда. HA 2026.3+ поддерживает локальные изображения для кастомных интеграций; дополнительные настройки для значка интеграции не нужны.

Для карточек при желании скопируйте `www/vdsina` в `/config/www/vdsina`. Доступны `/local/vdsina/icon.png` и `/local/vdsina/logo-white.svg`; белый логотип предназначен для тёмного фона. Картинки взяты с официального сайта VDSina; SVG-маска адаптирована по цвету для светлой и тёмной темы.

## API и проверки

Используется официальный публичный API: account, account.balance, server, server/ID и server.stat/ID. За цикл выполняются 3 запроса плюс два для каждого не удалённого VPS. Подробности серверов запрашиваются с ограничением до четырёх одновременных запросов.

Клиент сначала использует Bearer из текущей OpenAPI-схемы. При HTTP 401 он один раз пробует голый токен, как в старой документации, только на том же выбранном домене. Переадресации не выполняются, между .com и .ru токен автоматически не переключается. Интеграция использует только GET; кнопок перезагрузки, переустановки или удаления VPS нет.

Проверено: компиляция Python, JSON-файлы, 12 офлайн-тестов API (ошибки, авторизация, null, удаление сервера во время опроса, IP старого/нового формата, защита от ложного нуля и нечисловых значений). Дополнительно выполнены проверки с имитацией интерфейсов HA: формы, интервал 60 минут, смена токена, отклонение другого аккаунта, динамическое добавление сущностей, стабильность ID, доступность при сбоях и кнопка обновления.

Добавлен отдельный регрессионный тест единиц всех сенсоров аккаунта и даты прогноза без наследуемого атрибута единиц. Всего 13 тестов, все прошли: проверены направления трафика, границы календарного месяца, единицы, лимит и процент, а также изолированная ошибка статистики.

Реальный запуск внутри Home Assistant и доступ к вашему аккаунту не проверены. После установки проверьте появление устройства, баланс, IP, статусы и кнопку обновления. При ошибке пришлите текст из журнала без API-токена.

Офлайн-тесты для разработчика (Python 3.11+ и aiohttp):

```bash
python -m unittest discover -s tests -v
```
